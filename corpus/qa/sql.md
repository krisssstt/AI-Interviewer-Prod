# SQL для тестировщика: NULL, соединения и группы

Авторский учебный материал проекта, редакция 1. Справочная основа: PostgreSQL 16, Queries и Comparison Functions. SQL-примеры предназначены для чтения и анализа; приложение не запускает произвольный пользовательский код.

## NULL и трёхзначная логика

NULL представляет отсутствие известного значения. Обычные сравнения с NULL дают UNKNOWN, а WHERE сохраняет только строки, для которых предикат TRUE. Поэтому `deleted_at = NULL` не является корректным способом выбрать отсутствующие даты; применяется `deleted_at IS NULL`. Для противоположного случая используют `IS NOT NULL`. Проверка `x <> 5` не включает строки с NULL в x.

При тестировании нужно различать NULL, пустую строку и числовой ноль: это разные состояния, если схема и требования явно не задают преобразование. COUNT(*) считает строки, COUNT(column) — только ненулевые значения указанного выражения. Если сумма или среднее рассчитываются по nullable-столбцу, ожидаемый результат следует вывести из конкретной SQL-семантики.

## INNER JOIN и LEFT JOIN

INNER JOIN возвращает пары строк, удовлетворяющие условию соединения. LEFT JOIN сохраняет каждую левую строку; при отсутствии совпадения правые поля дополняются NULL. Если справа несколько совпадений, одна левая строка может породить несколько строк результата. Поэтому количество строк после JOIN нельзя считать количеством уникальных левых сущностей без анализа кратности.

```sql
SELECT u.id, o.id AS order_id
FROM users AS u
LEFT JOIN orders AS o ON o.user_id = u.id;
```

У пользователя без заказов останется строка с NULL в order_id. Условие `WHERE o.status = 'paid'` отбрасывает такую строку: сравнение NULL со строкой не даёт TRUE. Если требуется сохранить пользователей без подходящих заказов, условие о статусе следует рассмотреть в ON в соответствии с требуемым результатом. Перенос условий между WHERE и ON может менять смысл внешнего соединения.

## WHERE, GROUP BY и HAVING

WHERE фильтрует исходные строки, GROUP BY формирует группы, HAVING ограничивает группы после агрегации. Для выбора клиентов с более чем тремя заказами используется группировка по клиенту и `HAVING COUNT(*) > 3`. Условие на отдельный статус заказа обычно относится к WHERE до группировки. ORDER BY определяет сортировку и не заменяет фильтрацию.

```sql
SELECT user_id, COUNT(*) AS orders_count
FROM orders
WHERE status = 'paid'
GROUP BY user_id
HAVING COUNT(*) > 3;
```

## Подготовка проверочных данных

Для JOIN подготовьте строки без совпадения, с одним и с несколькими совпадениями. Для агрегатов нужны пустой набор, одиночная группа, несколько групп, NULL и значения на границе HAVING. Ожидаемый результат следует рассчитывать на небольшом наборе вручную и сверять с бизнес-требованием, а не с похожестью запроса на эталонную строку.
