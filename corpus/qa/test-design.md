# Тест-дизайн: эквивалентность и границы

Авторский учебный материал проекта, редакция 1. Термины используются в учебном смысле с ориентацией на ISTQB CTFL; текст не воспроизводит защищённый учебник или экзаменационные задания.

## Классы эквивалентности

Классы выделяют на основании предполагаемого одинакового поведения системы для группы входов. Для целочисленного поля с допустимым диапазоном 1–100 можно выделить три класса по допустимости: меньше 1, от 1 до 100 включительно, больше 100. Из каждого класса выбирают представительные значения. Это сокращает число проверок, но корректность разбиения зависит от требований и выбранной модели поведения.

Положительность сама по себе не образует допустимый класс в этом примере: 101 положительно, но недопустимо. Чётность тоже несущественна, если по ней нет отдельного правила. Неверный тип, отсутствие значения, NULL и пустая строка требуют дополнительных классов, когда интерфейс допускает такие входы. Разные правила валидации могут потребовать более подробного разбиения.

## Анализ граничных значений

Ошибки часто возникают на переходах между классами. Для дискретного целочисленного возраста 18–65 включительно трёхточечная проверка каждой границы включает 17, 18, 19 и 64, 65, 66. Значения отражают недопустимую сторону, саму границу и ближайшую допустимую сторону. Двухточечный вариант использует другой объём проверок; метод и ожидаемое покрытие нужно назвать явно.

Для денежных сумм с точностью до копейки соседним значением может быть 0.01, а не 1. Для строки важны единицы длины: байты, Unicode code points и видимые пользователю символы не всегда совпадают. Для даты требуется учитывать календарь и часовой пояс. Нельзя переносить целочисленный набор границ на любую область без определения шага и семантики.

## Практический порядок работы

Сначала запишите правило допустимости и ожидаемый результат, затем выделите классы и границы. Для каждого теста укажите вход, предусловия и проверяемый эффект. Добавьте негативные проверки типа и отсутствия значения. Если правила взаимодействуют, например возраст и тип документа, одного одномерного разбиения недостаточно: пригодятся таблица решений и проверки сочетаний.

## Типичные ошибки

Проверка только середины диапазона не покрывает границы. Проверка только двух допустимых концов не проверяет отказ за пределами. Случайные значения не гарантируют покрытие классов. Большое число почти одинаковых тестов не заменяет ясную модель и ожидаемые результаты. При неполном требовании нужно указать неопределённость и запросить правило, а не придумывать его незаметно.
