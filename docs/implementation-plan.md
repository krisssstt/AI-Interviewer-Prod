# План реализации

| Этап | Зависимость | Критерий завершения |
|---|---|---|
| 0 Аудит | — | Исходник сохранён; факты и базовые проверки записаны |
| 1 Архитектура | 0 | Требования, компетенции, модель данных, ADR и план |
| 2 Сквозной сценарий | 1 | Вход → серверный вопрос → оценка → БД → существующий UI |
| 3 Сессии | 2 | Состояния, пауза, история, контроль доступа, повтор ответа |
| 4 Корпус | 3 | Версии, extraction, chunking, embeddings, pgvector, retrieval и worker recovery |
| 5 Генерация | 4 | Реальный адаптер модели, JSON validation, учебный цикл, лимиты |
| 6 Оценивание | 4–5 | Сохранённые критерии, LLM-оценки, retry, injection tests |
| 7 Персонализация | 3,6 | Диагностика и сохраняемый адаптивный план, независимость подтверждения |
| 8 Полный UI | 2–7 | Все обязательные страницы интегрированы; дополнительные честно ограничены |
| 9 Эксперименты | 4–8 | Независимая оценка поиска/генерации/оценщика; безопасность и нагрузка |
| 10 Выпуск | 9 | Compose с PostgreSQL/pgvector проверен, backup/restore и демонстрационный цикл |

Интеграция и проверки выполняются на каждом этапе. Промежуточный серверный сценарий с тестовыми вопросами не означает завершение QA-направления.

Backlog: Backend/Frontend/Data Analyst (с отдельным корпусом и приёмкой); SMTP reset; OAuth GitHub; OCR; голос; sandbox выполнения кода; внешние уведомления; геймификация. Локальные данные прототипа не импортируются автоматически как достоверные оценки.
