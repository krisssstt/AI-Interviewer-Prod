# Эксплуатация

Локальный запуск и актуальная функциональность — [README](../README.md). Производственная публикация не выполнялась и не поручена.

## PostgreSQL / Compose

Подготовлен `compose.yaml`: PostgreSQL 16 с pgvector, API и отдельный worker. Создать `.env` по примеру, добавить `POSTGRES_PASSWORD` с собственным значением; не использовать SQLite DATABASE_URL для запуска контейнеров. Команда: `docker compose up --build`. API на `http://127.0.0.1:8000`; миграции и idempotent seed выполняются перед Uvicorn, worker ждёт readiness API. DB port наружу не публикуется. **Здесь Docker отсутствует, конфигурация ещё не проверена запуском.** Расширение vector создаётся миграцией, используется точный поиск без ANN для малого корпуса.

Для отдельного API с существующим PostgreSQL: `DATABASE_URL=postgresql+psycopg://...` в окружении, `alembic upgrade head`, seed, Uvicorn. В production задать HTTPS origin и `COOKIE_SECURE=true`; текущий Compose предназначен для локального запуска без TLS. Многопроцессная корректность PostgreSQL требует отдельного integration-прогона.

## Миграции и данные

Резервная копия до миграций; `alembic current`, `alembic upgrade head`, `alembic check`. Не запускать destructive downgrade на пользовательских данных. Seed создаёт отсутствующие записи и не обновляет существующие версии; новое содержание публиковать новой версией.

SQLite: остановить API и скопировать `interviewer.db` в защищённое место, восстановить копированием при остановленном API. Для работающей БД использовать `sqlite3.Connection.backup`, а не копировать открытый файл. PostgreSQL: `pg_dump -Fc` в защищённый файл; восстановление `pg_restore` сначала в отдельную пустую БД, проверить миграцию, health и выборку результатов; только затем переключать приложение. Реальный restore PostgreSQL здесь ещё не выполнялся. Не коммитить dump.

## Диагностика

- `/api/health`: 503 означает отсутствие миграционной таблицы; `ai=not_integrated` честно отражает состояние.
- 401: срок cookie истёк или сеанс отозван; вход заново.
- 403: проверить APP_ORIGIN, cookie и X-CSRF-Token; не отключать CSRF.
- 409: конкурентный запрос или повторный ключ с другим payload; повторить исходный запрос с тем же ключом/обновить состояние.
- 429: дождаться Retry-After; rate windows хранятся в БД.
- 503 reset: SMTP не интегрирован, письмо не отправлялось.

Логи Uvicorn не содержат bodies/паролей. Не включать SQL echo в production. Внешнему reverse proxy не доверять forwarded IP без явной настройки; текущее приложение лимитирует по реальному peer address. Очистка истёкших auth_sessions ещё требует служебной команды; rate_windows очищаются при новых запросах. Документы представлены UTF-8 текстом в БД, отдельного файлового volume пока нет.

## Worker и корпус

Второй терминал: `.venv/Scripts/python -m backend.app.worker --watch`; ограниченный прогон: `--limit 1` без watch. Это процесс обработки, отдельно от API. В Compose он запущен отдельным сервисом, Ollama ожидается на host.docker.internal:11434. Ollama не включена в Compose и модель автоматически не скачивается.

`OLLAMA_URL`, `EMBEDDING_MODEL`, `EMBEDDING_REVISION`, `EMBEDDING_DIMENSIONS`, `AI_TIMEOUT_SECONDS` — параметры в .env. Для nomic-embed-text ожидается 768 измерений. Изменение весов требует новой revision и запроса reindex на экране документов. Модель нужно загрузить в Ollama отдельно; автоматическое закрепление digest ещё не реализовано. Не помечать индекс готовым при недоступном сервисе.

Задание хранится в БД: queued/running/retry/completed/failed, до 3 попыток. Lease 300 секунд, просроченное задание забирает новый worker; попытки учитываются, исчерпание lease не даёт бесконечных повторов. Перезапустить worker после аварии, дождаться истечения lease; проверить статус по `/api/knowledge/jobs/{id}` под разрешённой сессией. При embedding failure материал text_ready доступен текстовому поиску. Повторить вручную/reindex после исправления провайдера; неизвестные ошибки не превращать в completed.

Администратор: `.venv/Scripts/python -m backend.app.admin email@example.com`; отзыв `--revoke`. Эта команда требует прямого доверенного доступа к БД. API регистрации и профиль не могут назначать роль. Общие материалы обновляются новой версией на экране документов. Поддерживаются TXT/Markdown; UI-файл до 20 КБ, API text до 30000 символов и общий HTTP-body до 64 КБ. Поэтому длинный многобайтный JSON может получить 413; текст формы сохраняется.

Удаление через API каскадно удаляет все версии/фрагменты/embeddings/jobs; после внешнего вызова worker проверяет наличие задания и токен аренды. Проверено тестом удаление во время вызова. Бинарные оригиналы не хранятся и не принимаются. Резервная копия БД включает весь текущий текстовый корпус и очередь.
