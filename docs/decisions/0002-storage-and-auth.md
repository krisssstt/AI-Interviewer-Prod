# ADR-0002: хранение и сеансы

Контекст: Docker недоступен на машине разработки. Нужны работающие локальные проверки и целевой PostgreSQL.

Варианты: ждать Docker; заменить стек SQLite; поддержать SQLite для разработки с целевым PostgreSQL.

Решение: SQLAlchemy с DATABASE_URL, PostgreSQL 16 + pgvector в Compose; SQLite только для быстрой локальной проверки. Миграции обязательны, create_all на старте приложения запрещён. PostgreSQL-специфичный поиск проверять отдельно; SQLite не доказывает работоспособность pgvector.

Авторизация: случайный непрозрачный токен в HttpOnly SameSite=Lax cookie, в БД только SHA-256 токена. Пароли Argon2id через pwdlib. Серверный срок и отзыв, без JWT и токенов в localStorage. CSRF: привязанный к сеансу токен в HTTP-заголовке для мутаций; login/register требуют JSON и проверку Origin при наличии. HTTPS/Secure cookie в production. Лимиты авторизации хранятся в БД, работают между процессами.

Последствия: нужны cleanup истёкших сеансов/лимитов и периодическая ротация; сейчас нет автоматического импорта локальных аккаунтов. Полная проверка PostgreSQL/Compose — отдельный обязательный пункт выпуска.
