# ADR-0003: текстовый корпус, очереди и заменяемые embeddings

Контекст: нужны реальные тексты, provenance, ACL и воспроизводимая обработка. Docker отсутствует; доступной модели пока нет. URL-каталог и keyword-ответы не заменяют RAG.

Варианты: ждать всю инфраструктуру; имитировать embeddings; реализовать хранилище, worker и честные независимые режимы поиска.

Решение: документы TXT/Markdown через ограниченный JSON upload (без удалённого fetching), private/public scope, immutable версии, chunks с section/offset. Собственный корпус из 12 учебных материалов автоматически загружается seed; внешние URL используются как справочные ссылки, их содержимое не копируется и не считается сохранённым. Доступ к общей базе на запись — только явная роль администратора; назначается локальным оператором, не API регистрации.

Индекс: PostgreSQL pgvector, точный cosine search по фильтрованным embeddings выбранного model_key; ANN пока не нужен для малого корпуса. Лексический PostgreSQL FTS/simple и SQLite lexical overlap — разные явно обозначенные реализации. Hybrid объединяет ранги RRF. SQLite векторный режим не имитирует: возвращает 503. Контекст до 12000 символов; max 10 результатов. Для SQLite предельная выборка 1000 фрагментов — ограничение прототипа, не масштабируемое production-решение.

Embedding port — `Embedder`, реализация Ollama `/api/embed`, batch ≤8, timeout, проверка числа/размерности/finite/nonzero, запрет скрытой truncation. model_key = model@revision:dimensions. Меняя веса, оператор обязан изменить revision и переиндексировать; старые векторы сохраняются отдельно. Автоматическая проверка digest модели ещё не реализована — mutable model tag остаётся известным риском для строгой воспроизводимости.

Очередь в БД: queued → running → completed/retry/failed; lease 300s, bounded 3 attempts, exponential backoff. Просроченная аренда возвращается в работу другим процессом. Перед внешним вызовом транзакция закрывается; токен аренды проверяется при фиксации. Готовый текст доступен отдельно от embeddings. Удаление источника во время внешнего вызова не воскрешает запись. Worker отдельно от API, режим batch или watch; без критичного состояния в памяти.

Chunking: структурные абзацы/заголовки, fenced code/table блоки не разрываются. Размер 2400 символов — временная конфигурация, сохранённая в chunker_version. Development-сравнение 800/1600/2400 не выявило различий на малом наборе, оно недостаточно для окончательного выбора. Oversized blocks >12000 или >64 chunks отклоняются явно. Форматы PDF/DOCX/OCR не реализованы и не маскируются пустым извлечением.

Последствия: текстовый поиск проверяем без LLM; полный векторный и hybrid сценарии требуют живой PostgreSQL/Ollama проверки. Строгая неизменность старых training snapshots сохраняется; следующие AI-задания должны фиксировать document_version/chunk ids, prompt/model metadata. Сформированных ИИ-артефактов сейчас нет; политика удаления частного контекста из них потребуется до этапа 5.

Официальные контракты: [Ollama API](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml), [pgvector SQLAlchemy](https://github.com/pgvector/pgvector-python), [pgvector cosine operations](https://github.com/pgvector/pgvector).
