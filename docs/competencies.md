# QA-компетенции v1

Авторитетные записи: `backend/app/competencies/seed_data.py`, загружаются seed и доступны `/api/catalog` после входа. Первое направление — QA. Каждая запись содержит description, prerequisites, levels, task_types, criteria, sources.

| ID | Проверяемое умение | Предварительные знания |
|---|---|---|
| qa-http-methods | Различать безопасность/идемпотентность методов | — |
| qa-http-status | Интерпретировать статусы и 401/403 | — |
| qa-http-cache | Условные запросы и ETag | http-status |
| qa-api-contract | Статус, схема, бизнес-инварианты | http-status |
| qa-api-access | Контроль доступа к объектам | api-contract |
| qa-api-retry | Повторы и идемпотентность операций | http-methods, api-contract |
| qa-sql-null | NULL и трёхзначная логика | — |
| qa-sql-join | LEFT JOIN без совпадений | sql-null |
| qa-sql-groups | WHERE/HAVING | sql-null |
| qa-design-boundary | Границы дискретного диапазона | — |
| qa-design-partitions | Классы эквивалентности | — |
| qa-logs-diagnosis | Trace-корреляция, симптомы и гипотезы | http-status |

Уровни начального набора — Intern/Junior, текущие задания Intern. Текущий проверяемый тип — choice; open обозначен planned и не предлагается как работающий. Для choice критерий correctness с весом 1, 0/100 за точный выбор. Для открытых заданий потребуются отдельные критерии обоснования, анализа и допустимых альтернатив до публикации. Нынешний банк — по одному заданию на компетенцию, недостаточен для надёжной диагностики.

Источники — RFC 9110, PostgreSQL 16 Queries, ссылки ISTQB и OpenTelemetry, собственные формулировки и пояснения. Ссылки не являются загруженным корпусом, экспертной валидации вопросов пока нет.

Правила плана rules-v1 — рабочее допущение: минимум 3 **разных** самостоятельных задания и средний последних 3 ответов ≥80 для учебного подтверждения; повтор через 14 дней. Один и тот же запомненный вопрос не даёт подтверждения. Сейчас банк не позволяет подтвердить компетенцию — он должен быть расширен до этого шага. Посещение материалов не учитывается, подсказка исключает самостоятельность. Диагностика/practice/exam различаются в аналитике, а в плане самостоятельные ответы пока объединены с явным происхождением. Эти пороги настраиваемые проектные правила, не научная модель квалификации; перенос в конфигурацию и валидация — этап 7.
